Developer Documentation

The contributor guide: how RadioFoundry is built, tested, released and extended. These pages describe process and tooling and link the specs for behavior; they don't repeat them. Users read docs/user.

Reading order

Step Page What it covers
1. Rules Contributing Branches, pull requests, clean-room rules, code, tests and docs a change needs
2. Layout Architecture The layers (core, hal, drivers, platform, boards), the tasks, where each feature lives
3. Build Building Toolchains, make targets, feature switches, build options, image size, flashing your own build
4. Test Testing Host tests, the UI simulator and gallery, sanitizers, fuzzing, HIL and the SDR bench
5. CI CI The workflows per push, per pull request and nightly; running each piece locally; coverage
CI runners and images The Gitea and GitHub runners, the csky-elf image, the HIL runner
Stack check The static worst-case stack depth of every task
6. Add a radio Adding a radio The files a board needs, board_t, the key map, bring-up order and records
The board registry board.toml and platform.toml field by field, what is derived, tools/boards.py
Adding a mode A digital mode in the codeplug, the firmware, the Codeplug Editor and zone sharing
7. Codec The codec How a radio's codec is merged and hosted, and what a merge tool must do
8. Release Releases The checklist, artifacts and manifests, sector maps, codec handling, the release workflow
The user manual PDF Building the manual and its workflow
9. Web site The web site The generated site, data sources, templates, translating, radio images, error logging
The web flasher The browser installer: modules, backends, backups, restore, version links
The Codeplug Editor The browser codeplug editor
Translating Adding a language to the radio and the site: catalogs, build switches, checks

To See

Add a feature switch build-config.md, "Adding a feature", then the matrix (feature-matrix.md)
Add a host test Testing, "Host tests"
Add a HIL test tests/hil/README.md, "Writing a test"
Change the UI docs/ux, ui.md, then make -C tests/host ui-gallery (Testing)
Add a radio Adding a radio
Move a radio from stock firmware The migration tools and specs are listed in the spec index
Cut a release Releases, "Checklist"
Preview the web site python3 site/build.py --serve (The web site)
