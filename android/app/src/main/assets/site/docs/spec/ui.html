The user interface

How core/ui implements the first-principles UX in docs/ux (principles.md, information-architecture.md, task-flows.md, wireframes/, usability-tests.md). The UX documents say what the radio does; this page says how the code is laid out, who owns the data behind each screen, and how the UI is tested without a radio.

Spacing on the displays under 200 px high (UI_TALL_PX): the status strip and, from 100 px high, each list row take one pixel more than the text cell, so lines never touch (easy to read comes before one more row; principles.md 5). The board's safe-area insets (hal_display_t.inset_*) are outside the drawing area (gfx_width / gfx_height), for panel edges hidden by the case (for example 5 px left and right under a lens). At 160x120i5 a list shows 7 rows, at 160x128 7, at 240x320i10x5 11, at 128x64 5. The 240 px class keeps 6 px between rows and a separate title row; uiSim --layout fails a class whose row pitch drops below these. A narrow portrait panel (120x160) keeps the 128 px class's small font (24 characters a line) and takes the 160 px class's channel and talk target fonts. Home's Activity region shows the last caller on two lines (name, then "TG 91 11s ago") where it has the rows for them, else one line where the name gives way first; a single line ("No calls heard yet") is centered in the region. While a hardware option is pending (board_hwopt_pending: one the board asks for, or one waiting for a restart) the idle region says so first, in the warning color ("Set: Board revision", or "Restart to apply"), with "Transmit waits for it" under it where there is a second line, and the hint row gives the place to set it ("Settings>Advanced>Hardware") or "Turn the radio off and on". PTT then shows the same reason (TXDENY_HWOPT). Text that doesn't fit is shortened (an alternate, the name dropped, then an ellipsis), never drawn in a smaller font.

A page title is in Title Case: every word capitalized except a, an, the, and, or, to, of, in, on, for and by inside the title; acronyms and units as written ("Unsaved Changes", "RX Group List", "Single-Freq Repeater", "Send To"). A fixed prefix ahead of a name is lowercase in the middle ("Talk to Ops", "Zone for A"). Names and counts in a title ("1 of 3", a zone's name) are shown as stored. List rows, values, hints, toasts and banners keep sentence case, so the row that opens a page can differ from its title: the Settings row "Talk & listen" opens "Talk & Listen". A page title is centered on the screen at every display class, moved only as far as it must to clear what shares its row (the state pill, the lock, the unread count).

The hint row is groups separated by two spaces ("OK open # more Back"). The group for the Back key (it starts with "Back") is drawn against the right edge, under the key; the other groups run from the left, and those that don't fit are left out whole from the right. A toast is one centered line instead. A banner or a two-line toast starts in a gap between lines of the screen under it (a row all one color), never through a line of text.

Hints and toasts call the QUICK and CONTEXT keys * and #. A radio without those keys gives its own names (board.quick_label, board.context_label: for example a front panel's own key names), and each * or # that stands alone is drawn as that name ("OK Menu P1 Quick"). On a radio with no digit keys a hint group that starts with a digit ("0-9 find") is left out. Toasts keep their numbers.

Text is shortened with a middle ellipsis only as a last resort (P5 allows it for names on Home). Before that:

  • A list row keeps its label whole and gives the value the room left: values carry text alternates (font.h) down to a short form or nothing (Hub's zone name, Find's kind, Zones' "Here, 16 channels" / "Here, 16 ch" / "Here", ages: "11s ago" / "11s"). A row marked UI_ITEM_PREVIEW (a message) is cut at its end, at a word.
  • Hints and toasts take the longest alternate that fits; a toast that still doesn't fit takes a second line above the hint row. Banners give the title and the text two lines each ("Call alert from" / "Jodi Ruiz"), and a message banner shows two lines of the message from the inbox.
  • Home's talk target line (DMR target or FM frequency) drops to the small font as a whole, then takes the target's short form; a frequency is never shortened. Large-text Home picks the largest font each line fits in, and takes the short form before it would go below the medium font. The short form of a talkgroup is its number ("TG 91 World" becomes "TG 91"); of a private contact, its name ("Joe Smith 9991234" becomes "Joe Smith"). A contact's ID alone says nothing at a glance, so it is what goes. An ID without a contact is shown as the ID.
  • While a VFO frequency is being typed in dual watch, its selected pane shows the digits and blanks for the remaining places in place of the old frequency, including on Large text Home. The other pane keeps its frequency. Back removes a digit; OK or # tunes the selected pane.
  • The RX and TX screens put the number in the title ("TG 91") and the talkgroup's or contact's name on a line of its own; a talker alias takes two lines when it needs them. A private call's title says "Private" where a group call's says "TG": "Private 9991234" while transmitting (just "Private" where that doesn't fit), "Private to you" or "Private to Joe Smith" while receiving. The TX screen's target line follows the short form rule above, and its detail line ends in "Private" or "Group". The word is the cue, not a color: the privacy (encryption) marker is "Priv" in blue, and a private call is not encrypted.

uiSim --ellipsis (section 7) lists what is still shortened; uiSim --layout fails the build on a middle ellipsis with ordinary content.

When entering a list screen, if the screen has not set a nonzero focus, select the first row that is neither informational nor disabled. If every row is one or the other, select the first disabled row (a text row is never focused). Returning with Back preserves the parent focus; manual navigation can still reach disabled rows to explain why they are unavailable.

Core code never includes a board header and never tests a radio define. What differs by radio comes from the board descriptor: the display geometry and insets (hal_display_t), and the key map (board.keymap), which turns keys into logical actions (hal_input.h).

2. Screens and the stack

The stack holds up to 6 frames; Home is frame 0. Each screen is a ui_scr_def_t (ui_nav.h): a name (the debug link's ui.screen), flags, and callbacks for list rows, SELECT, CONTEXT, the talk target of the focused row, a title, a body, raw keys, drawing and entry. List screens need only count and item; the generic list code does focus, scrolling, numbered shortcuts (SF_NUMBERED: 1-9, then 0 for the 10th row; later rows have none), T9 filtering (SF_FILTER), and the long-press target.

A filtered list's rows are raw rows (raw_count, raw_label) that have a label and, with keys typed, match them. With keys typed the list is the first UI_FILTER_MAX (128) matches. With none it is every row: the first 126 are kept in an index, and in a longer list its last two slots are a cursor (its row and raw row) stepped over the raw rows, so a list of 1024 contacts scrolls to its end (and Up from the top wraps to it) without RAM for a full index. A jump to the end steps over every raw row once.

A record a row costs a flash read a row, about 0.2-0.3 ms each on a radio with polled SPI flash, so the long lists (every contact, every channel) give two more callbacks. raw_each gives every row's label in one pass, a block of records a read (codeplug_contacts_each, codeplug_channel_names_each); with no key typed only which rows exist counts, and a list of channels then reads nothing (the in-use map is in RAM). raw_used says whether a row exists without its label, for the cursor's steps. With 1024 channels a key took 0.34 s before, 0.11 s after; opening the list 0.29 s before, under 10 ms after. A list without them reads its rows one by one.

  • BACK with unsaved changes opens Unsaved Changes (discard): "No, keep editing" first (the default, P7), then "Yes, discard". Long BACK still goes Home (P3) and drops the copy without asking.
  • Save checks the copy first and names the first problem in a toast: an empty name, RX out of every band, TX out of the transmit bands on a channel that isn't RX only, a DMR channel whose RX takes no DMR ("Receive only band: set FM"), a DMR channel without a TX contact unless it is RX only (the contact is whom PTT calls).
  • DMR goes wherever FM goes: any band of the table, receive-only ones included, but never a listen band (the air band on a radio with AM receive, the broadcast receiver's range). radio_listen_band() (core/radio/radio_bands.h) is the rule, the same one the VFO's mode change follows. A typed RX in a receive-only band makes the copy RX only, and FM only in a listen band. A DMR channel in a receive-only band, or on a radio with no transmit band, saves RX only.
  • Save writes with codeplug_set_channel as a storage job (ui_svc_write_channel), like Save to channel, so the UI never waits for a flash erase. A failed write raises UI_EV_SAVE_FAILED. The radio core re-reads the channel in use when codeplug_serial() changes, so any save drops its temporary changes, whichever channel was written. Whether the written channel is the one in use is decided when the job is posted, on the UI task.
  • Save as new channel writes the copy to the lowest free number (codeplug_free_channel) and opens that channel. "No free channel" when all 1024 are used. The new channel is in no zone until its Zones row or a zone's Add channel puts it in one (2.2); Copy here makes a copy that goes in a zone as it is saved.
  • New from current (the first row in Channels: New channel from current settings) fills a copy from what the radio uses now: the channel in use with its temporary changes, or the VFO. It opens as an unsaved channel at the lowest free number, named after the source with a number appended (or the frequency, from the VFO).
  • OK on Mode steps FM, DMR, P25, NXDN, then the channel's own kind, and round to FM. A step is offered where it can run: DMR with CONFIG_DMR; P25 and NXDN where the radio runs them (UI_FEAT_P25, UI_FEAT_NXDN, as the VFO's mode tile), and not in a copy made by Copy here, which takes its source's tag and has no block of its own; a kind of its own (a trunked channel, channel-modes.md) only on the channel opened as one, since its system can't be picked here. In a listen band only FM. The step back to the mode the channel was opened with restores it as it was, with its system and its NAC or RAN: a slip on the row is taken back by pressing on. A channel made P25 starts with NAC 293 both ways and squelch normal, one made NXDN with RAN 1 both ways at 9600 bit/s; either keeps its talk target and own ID, and Save writes it as a stored channel of the kind with that block. The row's changed mark counts the kind. Saving a stored channel of a kind as a plain one or one of another kind replaces its tag, so Save asks first on the discard screen, titled "Save as FM?" (or "Save as DMR?"; "Unsaved Changes" when it becomes another kind): the kind's name and "settings will be removed", "No, keep editing" first (the default; BACK is the same), then "Yes, save". Save as new channel takes nothing from the stored channel and isn't asked. Save as new channel and Copy here pass the source's number (ui_svc_write_channel's from, zone_op_t.from), so the copy takes the source's tag (channel-modes.md 2.4).
  • A P25 channel (a stored one, or New from current on a channel or VFO in P25) shows Mode as "P25" and only the rows P25 uses: Name, Number, Mode, NAC, RX, TX, Power, RX only, TX contact (the talk target), Own ID (the unit ID), Talkaround (On or Auto, the record's direct-mode bit), the TX time-out, Scan, Battery saver. Saving a plain channel in P25 writes a stored P25 channel from the radio's P25 settings (p25-codeplug.md 2.3).
  • An NXDN channel the same way: Mode "NXDN", then RAN and Rate in place of NAC, no Talkaround. Own ID over 65519 is refused ("NXDN IDs go up to 65519").
  • NAC shows the received NAC in hex, then the sent one where they differ ("F7E/293"); RAN the same in decimal. OK opens it. NAC: digits type hex digits (up to 3; a fourth starts over), Up and Down step the last one through 0-F (so A-F are reached), with none typed they step the whole NAC; BACK takes a digit back. RAN: a spinner 0-63 that also takes digits, as Color code. OK sets both ways, except F7E (every NAC) and RAN 0 (every RAN), which set the received one only; F7F (a repeater's) is refused ("F7F is for repeaters"). Rate: OK toggles 9600 and 4800 bit/s. A changed NAC, RAN or rate is saved with the channel (ui_svc_write_channel_air): the record, then the block over its tag's, the rest of the tag kept (p25_conv_save, nxdn_conv_save), or for a plain channel in that mode the block given with the talk target and talkaround from the radio's settings. Copy here shows no NAC, RAN or Rate row: the copy takes its source's tag, and they are changed on the copy afterwards.

Text entry supports both keypad conventions radios use: more presses of the same key (2: A B C 2 a b c) and # for the input mode, with BACK to delete (and to leave once the field is empty). In ABC and abc, keys 2-9 cycle their letters, the digit, then the letters in the other case; 1 cycles . - / , ' & ( ) @ _ ! ? 1, 0 a space, 0, + # *. The same key again within 1 s takes the next character; another key or the pause moves on. The title shows the mode ("Name ABC"). In 123 a digit types itself, and a held digit types itself in any mode (principles 3). CONTEXT (#) cycles ABC → 123 → abc (ABC first). BACK deletes the last character and, on an empty field, leaves without changing the name (the phone convention, the one exception to P4); QUICK (*) and Left delete too, and in text entry QUICK doesn't open quick settings. OK keeps the name. Without a keypad (class F): Up / Down step the last character (down past the space deletes it), OK adds the next one, long OK keeps. Names stop at CODEPLUG_NAME_LEN (16).

Typed rows (frequencies, the ID): BACK takes back the last digit, and with none typed closes the editor; OK keeps what is typed, and with nothing typed leaves the row as it was. A new RX frequency moves TX with it, keeping a repeater's offset. Where that offset would put TX outside every band, TX becomes the new RX (simplex). Own ID refuses a digit that would take it past 16776415 (the IDs above it are the network's: gateways, all call), and takes at most 8 digits.

2.2 Zone editor

With CONFIG_ZONE_EDIT a zone's list (zone) edits the zone. Every change is written at once, as a storage job (ui_svc_zone_edit), so there is nothing to save or discard and the UI never waits for a flash erase. Changes made faster than the flash takes them (a digit pressed again in Channel actions) wait in a queue of 4 and are written in order by one job; a fifth is refused. The job runs zone_edit_apply (core/codeplug/zone_edit.h), the same layer an import uses. A failed change raises UI_EV_SAVE_FAILED with the reason ("Zone full", "No room for another zone", "Already at the end", "That zone is gone", "That channel is gone", "Couldn't write the codeplug") and drops the changes queued after it, since they were made on a list that didn't happen. A change is checked whole before anything is written: a new zone with a missing or repeated channel is refused, and a Copy here whose zone can't be written deletes the channel it wrote. The lists read the codeplug again when codeplug_serial() changes and the queue is empty, so they show the change within a fraction of a second.

2.5 Languages

The UI's text is English in the source, marked for translation with a key (core/ui/i18n.h): TR(KEY, "...") returns the text in the language in use, TRN(KEY, "...") is a tr_id_t for a static table's entry that is translated where it is shown (screen titles, hints and empty texts are translated in list_draw), and TRX(KEY, "...") one for table text no catalog translates. With a language built a tr_id_t is the key's number and a lookup reads the language's table at it; a key without a translation shows its English, from the English table. Without any language built it is the English itself. Anything that isn't marked (names, numbers, the standard abbreviations) is shown as it is. The tables are built by tools/i18n.py from the marks and core/ui/lang/<code>.po, an entry per key (translating.md).

Monitor and Tone burst need raw edges, and Emergency the 1.5 s hold the input engine gives only a key whose long action is Emergency (a home key's long action is its home key action, so its hold would fire at the ordinary long press). Settings shows Default as what the key does on Home ("Prev zone", "Next zone"). With dual watch on, Home's arrows pick A or B (a home key left at Default still does).

  • The codeplug (a CPS or TFTP write): ui_svc_keys_poll reads the slots again when codeplug_serial() changes and rebuilds the key map. qdmr has no editor for them; a CPS that writes back an old image brings back its keys.

A request to save channel changes reports the reason when it cannot start: the VFO keeps its settings automatically, hotspot mode must end first, a stored channel must be selected, or another storage job must finish. The Home and Quick save keys and Actions > Save to channel use the same messages.

Auto power off is the UI's: ui_app_power_off_due() turns true after Settings > Power saving > Auto power off without use (keys, RX, TX, scan and hotspot count as use), with a banner and beep one minute before; the housekeeping loop (core/app) then powers off as for the knob, except that if the power is still on 2 s after releasing the latch it latches again, cancels the radio core's power off (radio_req_power_off_cancel) and raises UI_EV_POWER_OFF_FAILED ("Couldn't switch off / Turn the knob off"). The low battery warning is the UI's too: a banner (and the low beep while the radio core's level is still OK) at Settings > Power saving > Low battery warning, repeated every 5 minutes, reset 3 % above it.

Inbound events go through ui_notify() (a ring of 4, safe from any task) or, for packages the UI polls, through ui_svc_poll() once per UI pass. They become banners for 8 s: message received, delivered / not delivered, call alert, alert answered, radio check answered (with the round trip) or not, private call, emergency, hotspot started. A zone share offer's banner has no timer (ui_banner_t.hold): it stays over every screen until CONTEXT opens it, BACK (on any screen, before anything else) hides it, the offer screen opens from Tools, or the offer ends (zone-share.md 5.2).

Screens for features that are off (CONFIG_DMR, CONFIG_HOTSPOT, CONFIG_VFO_FM, CONFIG_VFO_DMR, CONFIG_SCAN, data features) are left out or dimmed with the feature. Some radios' default images have only a few KB free (docs/feature-matrix.md); the UI was about 50 KB when last measured (gfx + fonts about 11 KB, screens and behavior the rest). The frame buffer (40 KB by default) bounds the display: 240x320 at 16 bpp renders only in the simulator, which overrides GFX_FB_BYTES and GFX_MAX_ROWS. Every color board builds the 16-color frame buffer instead (GFX_INDEXED, bpp 4): 37.5 KB at 240x320, 9.6 KB at 160x120 and 10 KB at 160x128, against 150, 37.5 and 40 KB at 16 bpp. A mono board sizes the buffer to its panel (128x64 at 1 bpp is 1 KB). Drawing still takes RGB565 colors, and gfx.c keeps a 16-entry palette of the ones on the screen. An entry gets a new color only once nothing drawn since the last clear uses it; anti-aliased edges never take the last 4 free entries and otherwise get the nearest color already there. The debug link's screen captures read it as RGB565; /api/screen.bmp sends the indexes with the palette.

With CONFIG_NET_WEBCTL the web control page keeps a copy of the screen (docs/spec/tcp-services.md 5.1). gfx_flush marks each row it sends the panel, and webctl.c sends the marked rows and unmarks them. The UI task calls gfx_frame_begin before it draws and gfx_flush ends the frame, so the host link task, which runs above the UI, reads rows only between frames (gfx_frame_idle).

Without CONFIG_FONT_AA a screen uses at most 9 colors (the gallery, all 93 screens), so 4 bpp renders it exactly as 16 bpp does. With CONFIG_FONT_AA the edge grays add up to 20 colors on the busiest screen (Messages); on 14 of the 93 screens some edge grays and colors are replaced by the nearest palette entry, and some font sizes or colors can be slightly harder to read. The 160 px boards leave FONT_AA off for that reason.

8. Decisions and open points

  • Task flow 12 budgets 3 presses into the VFO, but flow 2 opens Zones on the current zone (so a zone two away is 2 presses); the VFO row is first, so entering it takes 4 (OK 4 Up OK). The test uses 4; the owner decides.
  • Power on radios with many levels: the Quick tile cycles three presets (low, the board's default, highest); the full list is in Settings.
  • Long BACK on Home no longer opens diagnostics (P3: one meaning per key); they are in Tools 7. The firmware boots into Home.
  • The long-press and key-repeat times are stored in settings_t and handed to the input layer (input_set_timing, clamped to 200..3000 ms and 40..1000 ms); auto lock locks the keys after its time without a key press (counted on Home and in menus alike; injected keys count). A key map with neither QUICK nor BACK (side keys only) is never locked by auto lock, since no key there unlocks it; a side key set to key lock still locks and unlocks.
  • Mic AGC and mic noise reduction are the vocoder's (DMR only). Each is dimmed ("Not on this radio") when the board's vocoder lacks the option (hal_vocoder_t.options), and in a build without DMR. While Mic AGC is on, Mic gain shows "AGC", is dimmed, OK says "Mic AGC sets the level" and the gain is step 5, the board's levels (FM too on a radio whose board sets the gain).
  • Mic gain acts on FM and DMR where the board sets it in its audio path (hal_radio_t.mic_gain), else on DMR only, in software before the vocoder (radio-features.md 3.6). The GPS options are stored but act on nothing (no GPS owner); they are dimmed on boards without CAP_GPS.
  • Freq trim (Advanced, the last row: Up from the top) is shown only on a radio whose board has hal_radio_t.ref_trim (UI_FEAT_REF_TRIM). The row shows the trim in ppm and opens the Freq Trim page (freq-trim, section 2).
  • Voice prompts are dimmed ("Voice prompts aren't built yet: no recorded speech").
  • Theme switches the color palette (dark, light, high contrast). Highlight color (Default, Red, Orange, Yellow, Teal, Light blue, Purple, Pink) and Filled status bar (Settings > Display, settings_t.accent) are for color displays too. On a 1 bpp display the three rows are dimmed ("Colors are for color screens"); a build without CONFIG_UI_COLOR (section 5) has no such rows. A color other than Default is the list and tile focus (with black text) and Home's channel number (on the light theme the number stays the text color: the light shades don't read on white). The filled bar (on by default) is reverse video: the status strip's background in the color (light gray with Default, white in the high-contrast theme), its text and icons black, the IDLE pill inverse on it; RX, TX and NO TX keep their own pill colors and words (P5). On it the pill is the strip's full height (a one-cell pill left a line of the strip's color under it) against the bezel, its corners rounded by two pixels. Left of the pill's middle the strip is the screen's background, so no strip color shows beside its left end. On the right a one-pixel black edge follows the curve: the pill colors are close in lightness to the strip colors, so hue alone would not separate them. Warnings on the strip (SCAN, MON, ROAM, unread messages, the lock, a low battery) keep a color: a dark shade picked per strip color, dark amber where it reads and dark blue on red, orange and pink, at least 5:1 on its strip after RGB565 rounding. The shades are light so black text reads on them (at least 7.5:1 after RGB565 rounding); the red is lighter and pinker than TX's red, and there is no green, which would hide the RX pill. Gallery: home_dmr*, home_plain, channels* (section 7).
  • The VFO has a mode of its own (dmr-voice.md 2.1). The Mode tile (tile 4 in the VFO only) switches it FM / DMR ("VFO: DMR", no "for now": it is kept), and in a build with only one VFO kind the tile is dimmed ("VFO: one mode in this build"). On a channel tile 4 is "To VFO" (dmr-voice.md 2.2): it copies what is in effect on the channel to the VFO and opens it on Home ("Copied to VFO"); a channel the VFO can't hold is refused with a toast. A channel has no temporary mode change any more. In DMR the quick menu is the DMR one: Timeslot, Color and Talk to change the VFO's own settings, with no dot on Home. The talk target picker lists the VFO's current target first ("Current"); both OK and hold OK keep the target for the VFO.
  • The privacy key is typed in decimal (Anytone 0..65535). Number rows take typed digits; a value outside the range or between steps is refused with the range. Only key slot 1 is reachable from the menu.
  • Switching USB to network has no confirmation (P7: reversible); the info page says what stops and how to get back.
  • A failed message isn't kept for a retry: the banner says "Not delivered: send it again".
  • Compose offers canned texts only ("OK", "On my way", "Call me", "Can't talk now"), sent in the language in use (2.5); free text is dimmed.
  • Deleting a message has no undo (sms_inbox_delete removes it from the RAM inbox).
  • Save to channel and the permanent talk target write the codeplug as a storage job on the housekeeping task, so the UI no longer stalls for the flash write. A permanent target must be a stored contact: a typed ID is set for now at once and the job then says "Not a stored contact: for now only".
  • One-shot PTT: the row with the focus in the picker or a list is handed to the radio core (radio_req_dmr_focus); PTT then talks to it once, and the radio follows it for a reply window (the reply time setting, else the codeplug's hang time) before going back to the channel's talk target. A channel change, the call ending outside the window, Reply cancel or a new manual target end it.
