Radioddity DB25-D PRO hardware

This page holds the facts a firmware needs to bring up the DB25-D PRO mobile: SoC, memory, pins, the two RF chips, display, storage, calibration, the PC link and the update path. The survey entry, with sources for the model and FCC facts, is in radios.md. The HR_C7000 itself (UARTs, timers, ADC, DAC, PIC, GPIO) is in hardware-dm32.md and its modem in modem-hrc7000.md; this page only says where the DB25-D differs.

Values marked (measured) were checked on a DB25-D PRO (firmware 909E.D6x.EARSAB.020) on 2026-10-16 or later, or on the SDR bench. (datasheet) is from a chip data sheet or the HR_C7000 user guide. (unverified) is not confirmed on a radio or in a datasheet.

2. Memory and image

Item Finding
Program flash XIP at 0x03000000. Boya, 2 MB (JEDEC ID 68 40 15), 4 KB sectors. QE (status register 2 bit 1) is set: the application sets it before it switches the controller to quad mode (measured)
Loader 0x03000000-0x0300BFFF (48 KB, 36 KB used), the vendor IAP loader. It's never in an update package (measured)
Application Linked at 0x0300C000; the loader jumps to its first byte. Raw image: no header, no checksum, no encryption. On a normal power-on the loader starts it only if its first 4 bytes are 2C 11 01 C0 (the entry of the vendor application, lrw r1, ...; mtcr r1, psr), else it stays in update mode; right after an update it starts it without looking (measured)
RadioFoundry's layout The first stage (boot/db25d, boot/README.md) in the 4 KB sector at 0x0300C000, carrying that signature; the application from 0x0300D000 (measured)
Clocks The loader leaves the PLL at 72 MHz (24 MHz × 24 / 2 / 4), APB 36 MHz, on both paths into the application. The vendor application never writes the clock manager, so it runs on those. RadioFoundry re-programs the PLL to the DM-32's 168 MHz CPU / 84 MHz APB (section 2.1) (measured)
Start-up state PSR 0x80000100, SP 0x50000, VBR 0x10000, cache set as on the DM-32
SRAM 0x10000-0x57FFF as on the DM-32. The vendor application uses 0x10000-0x525E0
Modem SRAM The vendor application copies its modem and vocoder tables to 0x18000800-0x18004F90

2.1 Clocks in RadioFoundry

Item Setting
Switch DB25D_FULL_CLOCK=1 (default, board.mk): CPU / AHB 168 MHz, APB 84 MHz as on the DM-32 (hardware-dm32.md 1.1). DB25D_FULL_CLOCK=0: no PLL change, 72 / 36 MHz as the loader leaves them. Both builds define HRC_LOADER_CPU_HZ = 72 MHz, which the stub hand-over uses (measured)
Limits The user guide (4.2.2.2) gives CPU and AHB up to 192 MHz, APB up to 96 MHz (typical 120 / 60). 168 / 84 is inside them. The NAND takes 133 MHz, the ST7735S writes at up to 15 MHz (datasheet)
Start-up The loader runs the CPU from the BPLL, which must not be reprogrammed under it. hrc_clock_init (RAM code, interrupts off, before the vector table is set up) saves CLK_MGR 0x010 / 0x024 / 0x028, sets the SoC clock select (CLK_MGR_CTRL bit 3) to the oscillator, clears the BPLL configure bit (bit 1), writes the 24 MHz / 1 × 28 / 2 / 2 word, USB / SDIO dividers and AHB:APB = 1:2 as the DM-32 does, sets bit 1 again, waits 100 us for the lock flag, then clears bit 3. The APLL (modem clock, bit 0) is left alone. If the PLL never locks within 2 s, the saved words go back. The XIP flash is switched to quad mode at divider 2 before, as on the DM-32; its SCLK follows the AHB clock (measured)
Timers, UART, SSI All derive from HRC_APB_HZ at build time: timer 2 (microseconds), the tick, the one-shots, UART divisor 46 for 115200 (0.9 % slow; 20 at 36 MHz is 2.3 % slow), NAND SPI0 divider 4 (21 MHz, 9 MHz at 36), display SPI2 divider 6 (14 MHz, 6 MHz at 36) (measured)
Bit-banged display Each phase of the clock line is written hrc_bitbang_repeat(APB) times (3 at 84 MHz, 2 at 36), so the phases stay over about 30 ns. Used only when the ADC 2 strap reads 50 or more (3.1) (measured)
Not clock dependent The BK4819 3-wire bus, key scan, APC ramp and TX settling use hal_delay_us (timer 2). ADC conversions run from the 24 MHz oscillator (user guide clock tree: oscillator / 10); the ADC and UART wait loops are counted, and are shorter in wall time at 168 MHz, still several ms (measured)
Modem The modem and codec clocks come from the APLL and the oscillator, not the BPLL (user guide clock tree), and hrc_clock_init doesn't touch them; the DMR code's assumptions are the DM-32's, which are 168 / 84 (datasheet)
Hand-over enter_stub and hrc_restart (the REBOOT path) call hrc_clock_restore_loader() first: SoC clock to the oscillator, the saved CLK_MGR words back, lock, SoC clock to the PLL, so the loader (which finds the clock manager as it left it, a soft reset only resets the CPU side) and the runtime stub see the clocks they expect (the universal stub measures timer 2 anyway and gets the rates in CONFIG, 7; it measured 35.6 MHz). Before it the UART drains; after it the divisor is set for 36 MHz (20). A power cycle resets the clock manager (hard reset), and the first stage (boot/db25d) runs before any RadioFoundry code, so the power-on stage catch always sees the loader's clocks even if RadioFoundry hangs at 168 MHz (measured)

Check the clock on a radio: the debug link's uptime_ms has to advance one second per second (timer 2 counts APB cycles, so a wrong APB shows at once) and the host link has to answer at 115200 (the UART divisor assumes 84 MHz).

3. Pin map

GPIO index as on the DM-32: 0-31 PTA, 32-63 PTB, 64-95 PTC. Levels are "high = on" unless stated.

3.3 Keys, encoder, power, LEDs, audio

Pin Use
PTB18, PTB20, PTB21, PTB22, PTB23 (50, 52-55) Key matrix drive lines, idle high, driven low one at a time
PTB9, PTB10, PTB11 (41-43) Key matrix sense lines, low = closed. PTB9 and PTB10 also carry one key each wired straight to ground (low with every drive line high)
PTA9 (9) Also read as a GPIO by the key code: the mic connector's line that carries PTT and the radio's RXD. RadioFoundry counts a low PTA9 as PTT only 50 ms or more after the last good UART byte and held low that way for 20 ms (drivers/input/sharedptt, gotchas 16.2), then on three scans in a row; the diagnostics line mic ends with ign N, the low scans ignored. The three-scan filter alone let debug link polling key the radio; with the gate, 30 s of polling gave ign 5 and no PTT press (2026-10-19, measured)
PTC11 (75) Hand mic PTT: high at idle, low while held. With no mic in the front jack it reads low from power-on and never changes (0 edges in 25 s, cable in or out), which keyed the radio at every start without a mic (issue #230). RadioFoundry counts a low PTC11 as PTT only once the line has read high for 100 ms since power-on, a mic plugged in (drivers/input/plugptt); the diagnostics line mic ends with mic once armed, nomic before. Plugging the mic in later arms it then. Pulling the mic out while armed reads as a held PTT, which the transmit timeout ends (with TX timeout Off, nothing ends it until power-off). On the radio (2026-10-27): no mic at power-on, no key-up (nomic); mic plugged in, mic, PTT keys and releases. PTB12 (44) Power key sense, low = pressed
PTB13 (45) Power latch: set at start-up, cleared to switch off

PTA17 (17) Unused, set high at init
PTB0, PTB1 (32, 33) Status LEDs, high = on: PTB0 green, PTB1 red (measured)
PTB14, PTB15 (46, 47) Audio path selects: audio on = PTB14 high, PTB15 low; off = PTB14 low, PTB15 high
PTA15, PTA24 (15, 24) Speaker enables, low = on: PTA24 the body speaker, PTA15 the mic speaker. Both high when audio is off. IO_DIPLEX1 bits 11 and 12 set (GPIO). PTA15 low also darkens the LCD backlight on the owner's radio, so RadioFoundry keeps it high and drives the body speaker only (measured)
PTC18 (82) Speaker source: high next to every main-chip AF on and side tone (analog squelch open, tone burst), low for the modem's audio (DMR call start, beeps, call end). Taken to select the main chip's AF (high) or the modem's line out (low) for the amplifier. RadioFoundry drives it low in DMR, high otherwise
PTA19 (19) FM broadcast audio enable
ADC 2 Board ID: display bus mode
ADC 6 RSSI (squelch and channel busy)
ADC 0, ADC 7 Neither is shown to be the supply, and no supply-voltage read is known. ADC 7 is a hysteresis input that drives an output of the LO chip (register 0x33, 4.3): below 465 the output goes high, above 527 low, in between it stays. The pin is 2 on a BK4819 LO, 4 on the FD6818 and AT1141. What ADC 7 measures and what the output drives are unknown (unverified). At a 13.5 V supply: ADC 0 reads 0, ADC 2 about 0, ADC 6 594 (no signal), ADC 7 742 (measured). ADC 7 follows the transmitter's load, not a slow temperature curve: keyed into a dummy load at the lowest power it fell from 726 to 559 in 1 s, below 465 in 3 s and to 425 by 10 s, and was back at 670 about 1 s after the transmission ended (measured). RadioFoundry reads it at every status poll, transmitting too (radio_db25d.c, db25d_lo_aux)

Speaker volume. The BK4819 init (table in 4.3) writes register 0x48 as 0xB3BF and then 0xB3B3 near the end, so the AF DAC gain nibble ends at 3. Neither ADC 0 nor ADC 7 is a volume knob, and the VOL/SQL key may be a squelch key rather than volume (unverified). RadioFoundry gives the radio a volume of its own: 16 steps (RADIO_VOLUME_MAX) on the AF DAC gain nibble (bits 3:0, the public BK4819 meaning), with the other fields of 0x48 left at 0xB3B3's upper bits. Step 0 is mute (register 0x47 to its mute word, and the chip's output off); steps 1..16 give nibble 0..15, the table being nibble = (step - 1) * DB25D_VOL_GAIN_TOP / 15 in radio_db25d.c (DB25D_VOL_GAIN_TOP is 15; lower it if the top steps distort). Nibble 3 is step 4; the default step 8 gives nibble 7. The dB per nibble step, and whether the top steps distort the speaker, are not measured (unverified). The debug link can set a step (radio-features.md 4.2). In DMR the chip's output is the modem's input (4.5): it gets the digital gain word 0xB174 (nibble 4) and the volume step comes back when the radio returns to FM. DMR voice and beeps leave the modem's codec line out instead (4.5), so the same step also sets the HR_C7000 line out gain (GCR_DACL, hrc7000_volume_db): 0 dB at the default step 8, 3 dB less a step below it (step 1 is -21 dB) and up to DB25D_PCM_VOL_TOP_DB (12 dB) at step 16; step 0 keeps the amplifier off. The radio sets volume_pcm, so beeps play at beep_level and the volume scales them on the way out. The dB at the speaker is not measured (unverified).

Switching the amplifier on (PTA24 low) pops, whatever the order of the other speaker pins (measured). So the board gives the radio core an amplifier hang (hal_audio_t.speaker_warm, speaker_hang_s 5 s, radio-features.md 4): after a key, PTT, reception or beep, PTA24 stays low with the source muted (PTB15 high) for 5 s, and the beeps and calls in that time play without the enable's pop. Only the first sound after a quiet spell still pops. On the radio the debug link's beep.warm went to 1 on a key and on a beep and back to 0 after 5 s, and the warm beeps carried no pop at the amplifier's turn-on (measured; test_speaker_beeps, a microphone at the speaker).

The front keys are power (PTB12), P1, P2, P3, VOL/SQL, TONE/T.SEL, B/E and the encoder push; there's no separate Menu/OK key (measured). Their matrix positions, found by pressing each key on the radio, with the key code the vendor firmware uses for the same position:

3.4 Hand microphone

The 16-key hand mic has its own MCU. Its PTT is a plain contact on PTC11 (3.3). Its keys are serial: while a key is held the mic sends three ASCII bytes, "K" and the key number as two digits, on PTA9 at 115200 baud 8N1, every few milliseconds (a frame takes about 300 us). Nothing is sent when the key is let go. PTA9 is also the PC link's RXD, so the host UART receives the frames, and the mic and the PC cable can't be used at the same time (measured).

Key 0-9 * (DWN) # (UP) P4 P5 P6 P7
Number 00-09 10 11 12 13 14 18

Numbers 15-17 weren't seen (measured).

4. RF chain

4.1 Architecture (PRO)

Superheterodyne with a 51.550 MHz IF (manual section 18.2). One BK4819 is the receiver and transmitter ("main"), the other is the local oscillator ("LO"):

State Main BK4819 LO BK4819
RX on f Tuned to 51.550 MHz, RX state Synthesizer at f + 51.550 MHz (high side): frequency in 0x38 / 0x39, state 0x30 = TX enable value so its output stage drives the mixer, level in 0x36
TX on f Tuned to f, TX state Off (0x30 = 0, 0x37 = 0x1D00)

Analog FM is modulated and demodulated by the main BK4819, not by the HR_C7000, which stays out of its FM modem mode.

The firmware reads register 0 of each chip at boot and writes the letters into its version string:

4.3 BK4819 registers (address: value, in order)

The register meanings are the BK4819's public ones; the values are what the vendor firmware writes.

Register Meaning
0x00 bit 15 soft reset
0x30 Enables. Main chip (bit 9 set in every state): 0x0200 idle, 0xBFF1 RX, 0xC3FE TX (VCO calibration, PLL / VCO, PA gain, mic ADC, TX DSP), 0xC3FA TX with the mic ADC (bit 2) off for a tone, 0x0302 during init. LO chip (bit 9 never set): 0x0000 idle, 0xC1FE its carrier-only transmitter stage
0x33 GPIO outputs: bits 14:8 disable an output, bits 6:0 its level. Pin p is bits 14 - p and 6 - p; written only when the value changes. The band flags, high for VHF (as GPIO3 on the older batches, 4.8): LO chip pin 1 is the RX band (bits 13 and 5), set before every LO tune; main chip pin 2 is the TX band (bits 12 and 4), set at every receive set-up and TX prepare. 0x43 Receive filter bandwidth: 0x3028 and 0x4048 (wide / narrow) (unverified). The channel set writes 0x30 = 0x0200, 0x52 = 0x028F, then 0x43 and 0x4F together: 0x3028 with 0x3332, or 0x4048 with 0x3D3C

4.4 FM transmit

The main chip transmits on f itself (4.1). The RF record carries the PA drive, the modulation pair and the two TX delays per frequency (6.4); only the PA drive and the delays act on the BK4819 path. The modulation pair and the TX center go to the C7000 modem's DMR registers, and the modem is never in FM mode (4.1), so analog deviation on this board comes from the chip's own registers: 0x40 (written before each transmission, 0x34D0 or 0x34A8 with a sub-audio tone), microphone gain 0x7D = 0xE34A, the same for 12.5 and 25 kHz (unverified).

More lead buys about 0.15 dB per 0.1 ms at the first symbol (3.6 dB under the settled level with 0.8 ms of lead, 2.5 dB with 1.5 ms), and a boost before the level's drive buys nothing: with boosts of 4 to 30 % held for 0.3 to 1.2 ms the output was back at 3 dB under 0.5 ms after the boost's end. So this level is timed by its edge (6 dB under 0.43 ms before the first symbol) and its first symbol is 3.3 to 3.7 dB under the settled level. The two levels above it creep the same way by less (2.3 and 1.2 dB under at the first symbol). An earlier set keyed the lowest level from a 1.5 ms window with a boost: it was 10 dB under its level at the slot's start, 0.25 ms into the slot before.

Tried and dropped (no change in the inbound counts): keeping the LO chip running through TX, a ramp down 0.45 ms before the last symbol (16 bits fewer per 72 frames, our last symbols at reduced power), and shorter waits in the TX on sequence. The modem's RF_MODE b25 phase averaging off made it worse (51 of 72 frames decoded). The extra errors stay in the first and third frame of each burst, at about 3 bits a burst, whatever the switch points: the receive chain settling after the retune, not the switch timing.

4.6 Frequency reference: the modem's bias

On the owner's radio both receive and transmit read 23 ppm low (10.6 kHz near 461 MHz) and DAC C changes nothing. The C7000 modem's DC bias registers are written at every receive set-up, in FM as well as DMR: SIG_CENTER 0x11000108 and RF_MOD_BIAS_CTRL 0x11000114 as in 6.4. The BK4819s have no VCO input, so the modem's two-point modulation puts its low-frequency half on the TCXO's control pin and this DC level sets the TCXO frequency; both chips share that TCXO, so receive and transmit move together (unverified; matches the measurement). The factory tunes the TX center byte with the radio transmitting, and nothing else on the page trims the frequency. RadioFoundry powers the modem (hrc7000_power_on_init) at init in every build and writes both words at init and at every rx().

The user's reference trim (radio-features.md 6.1) leaves this bias alone: it is the factory's tune and the DMR modulation rides on it. RadioFoundry retunes the BK4819s instead. A key-up now and then restarts the radio (reset.cause warm, no fault trace): a supply dip at TX on, also without the trim (1 of 3 plain key-ups on 2026-10-30). The HIL trim test waits 3 s after each trim before it keys, and may need a rerun.

6.1 Page header and the two copies

Offset Size Field
0x000 4 Magic "TUNE"
0x004 4 Save counter, u32 little-endian. The vendor tuning mode adds 1 on every save

At boot the vendor firmware reads 8 bytes of each copy. If both carry "TUNE", the copy with the higher counter wins and is copied over the other. If only one does, it's copied over the other. If neither does, the radio runs untuned ("No tune"). There's no checksum. RadioFoundry applies the same choice when it reads, without writing anything back.

6.2 Bands and frequency points

The page has two 1 KB halves with the same layout: 0x000–0x3FF for UHF and 0x400–0x7FF for VHF. The half is picked from the band of the frequency in use. Offsets below are UHF; add 0x400 for VHF. The few fields that exist only once are marked.

Most tables hold one value per frequency point, 8 points per band:

Point 1 2 3 4 5 6 7 8
UHF (MHz) 403.175 414.175 425.175 436.625 447.775 458.775 469.825 478.825
VHF (MHz) 136.125 142.125 146.125 152.125 156.125 162.125 166.125 173.125

A per-point table is one leading byte, then 8 entries in point order, so entry p (1–8) of size n starts at table + 1 + n·(p − 1). The leading byte isn't used by any per-point lookup.

Interpolation: for f at or below point 1, use point 1. Otherwise take the first point p ≥ 2 at or above f and interpolate linearly between points p − 1 and p, rounding half up. Above point 8 (478.825–480 MHz, 173.125–174 MHz), the vendor firmware reads past the table into the next one. RadioFoundry uses point 8 there instead.

The squelch table works by segment: 8 segments per band. VHF: below 142, 142–146, 146–152, 152–156, 156–162, 162–166, 166–173, from 173 MHz. UHF: below 410, then 10 MHz steps (410–420 … 460–470), from 470 MHz. A segment's upper edge belongs to the next segment.

What makes the range safe is the layer's foreign-data guard (nand-sectors.md 4): a block whose first or last page reads back clean, isn't erased and carries no RadioFoundry record makes the mount fail. Then nothing in the range is programmed or erased, the radio runs without stored settings, and the diagnostics page names the block. Clearing it is the owner's call. RadioFoundry never programs or erases outside the range, and never touches the factory bad blocks in it. The layer uses spare bytes 8-23 of each page and leaves 0-7 alone (the factory mark and the vendor marks at 4-5). A block the vendor firmware marked bad at bytes 4-5 counts as foreign.

8. Codec

The HR_C7000 vocoder library (V1.9.6) runs AMBE+2 in software on the CK803S and the frames pass through the CPU. RadioFoundry hosts it as on the DM-32UV (codec-dm32.md): the user's machine carves the codec out of the vendor firmware file or the radio's program flash into a slot in the image, and the firmware copies it to the board's codec window at the top of RAM at boot and moves the addresses its codec map lists (codec-placement.md). No codec bytes are in the repository or in a release.

The merge moves the codec's code into RadioFoundry's codec window, but not its tables. Hotspot CONFIG_HOTSPOT=y (default on): the MMDVM host port on UART1, simplex. The core's hotspot drives the same hal_dmr_modem_t as a call (tx_begin, tx_queue, tx_end) and keys through hal_radio_t.tx() in DMR mode, so it runs on the per-burst TX path of 4.5 (the dmrrf RF task) with nothing added to the board: whole calls and data go out as the host sends them, and a retune (rx()) disarms the keying until the hotspot arms it again. Not offered: the split-duplex roles (CONFIG_HOTSPOT_SPLIT=n: the driver has no continuous BS outbound, so the core would refuse the role). DMR receive check (passed on the owner's radio, 4.5): build with the vendor firmware file in codecs/ and make BOARD=db25d; flash rfoundry_db25d_codec.bin; with a DMR repeater or the SDR bench's DMR source on a channel of the zone, read the diagnostics page. In order: the codec line shows db25d-... and a non-zero tag; the sync counters move (the AF phase range isn't a level check on this board, 4.5; if nothing syncs, try the AF gain and RF_MODE knobs of 4.5); ts and si climb (the modem has slot timing); then V / H / T counts rise on a talk burst. Voice and the speaker route come last. stubtool --rfoundry-enter loads the stub into a DMR build's 0x1D000 span by itself (7).

DMR transmit check (passed on the owner's radio, 4.5; on a dummy load or into the SDR bench): key a DMR channel on the low power level. On the diagnostics page b (bursts keyed) and its pair (bursts ended) climb by 16 or 17 a second and stay equal after the key-up; L stays 0 or small. On the SDR bench: bursts in one timeslot, carrier on frequency, the ramp ending before the other slot, then sync and the voice header decoded. No sync with a clean carrier: try DB25D_DMR_TX_INVERT=1. Low deviation: compare the page's modulation byte (6.3, 0x067) with the value for the same frequency in the radio's own calibration.
