MD-9600 bring-up checklist

The MD-9600 port (make BOARD=md9600) builds, passes its host tests and runs on a radio. This is the order to try it in, what each stage proves, and what to change when it doesn't work. The unknowns are numbered as in hardware-md9600.md section 17. Every row names the knob in the source that the likely failure points at.

The radio is a TYT MD-9600 or Retevis RT90, any board revision (hardware-md9600.md 16). One image drives every revision; the revision is a stored setting (19.3).

The feature checklist, with every feature's required HIL tests and the last recorded result, is tools/bringup.py list --radio md9600. tools/bringup.py run --radio md9600 records a run (tests/hil/README.md). This page keeps the hardware steps and what to change when one fails.

Status (2026-11-02)

First radio: a V1-V3 board (its original firmware reported version 06.09), on a dummy load, no signal generator.

FM receive audio Loud at the bottom of the volume knob and overdriven. The HR_C6000 settings, FM_SW and the IF chip words were compared with the original firmware's and changed live without effect; whether the original firmware sounds the same on this radio is not checked

CTCSS 67.0 Hz too. DCS 023 normal from the same handheld opens it within about 0.5 s and holds for the whole transmission (2026-11-03), after the decoder's DCS slicer gained hysteresis: PA2 high-passes the DCS stream (corner near 18 Hz), and the old slicer missed 4 to 8 bits a word. The decoder reads PA2; PC3 carries the voice band without the tone. Encode is not written
FM receive, UHF Works: a handheld on 446.000 MHz, 12.5 kHz, at -57 to -73 dBm; the audio sounds the same as on VHF
DMR data receive Works: an unconfirmed ETSI IP text from the SDR bench's transmitter on 446.100 (CC 1, slot 1) lands in the inbox with its text, the CRC good and no reply sent (2026-11-03). Deleting it from the UI works
APRS receive Written (afsk_md9600.c: PC3 on ADC3, 9146 Hz), untested: no APRS traffic on 144.390 MHz in 12 minutes at the bench. Listening, the decoder sees the noise only (aborts, a few FCS errors)
VOX mic level PA3 is a level tap: 3-4 counts (VOX level 12-16 of 100) with the mic quiet, and a beep in the speaker doesn't move it. VOX on and off from Quick works. The level while speaking is not measured yet; VOX can't key while transmit is refused
DMR receive Works on UHF (446.100) and VHF (151.505), by hand: a group call from another radio (CC 1, slot 1) plays clearly, every voice burst received. The DMR modem counters are on the diagnostics page after the board lines
Transmit On in the build (CONFIG_MD9600_TX, CONFIG_MD9600_DMR_TX), once the board revision is confirmed. UHF, 5 W into a dummy load (section 5): DMR decoded burst for burst; FM with CTCSS and DCS passes the FM transmit HIL tests. VHF, 5 W on 151.5125 MHz: FM (12.5 and 25 kHz, CTCSS, DCS) and DMR checked off air (hardware-md9600.md 19.9.1). Every power level checked on a wattmeter on both bands (power-calibration.md 4)

0. Before anything

  1. Back up the radio while its original firmware runs: the data flash (codeplug, contact list) and the firmware version (hardware-md9600.md 15). RadioFoundry's open-firmware layout overwrites the codeplug area, and its settings claim erases 0x011000-0x01AFFF. RadioFoundry never writes the flash security registers (calibration and option block).

  2. Bootloader: DC off (the power key only puts the radio in standby), hold P1 and the orange key, DC on. The screen stays blank and the backlight blinks at 1 Hz (14.1). The radio's DFU interface string tells the bootloader from the original firmware, which has the same USB IDs and strings.

  3. Build and flash. With the radio's original firmware file in codecs/ the build also writes the image with the radio's own codec, build/md9600/rfoundry_md9600_codec.bin (codec-md9600.md):

    make BOARD=md9600
python3 tools/release.py --board md9600 --version v0.0.0-test --out build/dist
cd tools/rfoundry && python3 -m rfoundry flash ../../build/dist/rfoundry-md9600-v0.0.0-test.bin \
    --stock FILE --board md9600 --codec merge --yes

    Later updates go through the stub (stub/stubtool.py PORT --rfoundry-enter --board md9600 --write-app IMAGE).

  4. Board revision: V4A / V5 is detected at every start (the AK2365A read test, 19.3); on V1-V4 the installers store it after the first boot or ask for it. Check it with rfoundry_debug.py hwopt (state=ask until it is set) and the board view's rev.source and rev.ak2365; set it by hand (hwopt "Board revision" V1-V3|V4) if it asks. The diagnostics page shows the source and the read test.

  5. Codeplug: write one (CPS or tools/cps_client.py) before judging the channel screens. Until then the codeplug area holds the original firmware's own bytes. Writes are refused until the settings area is claimed (rfoundry_debug.py storage claim --out DIR, which saves the area first).

4. FM receive

Put the radio on a VFO frequency with a known signal (rfoundry_debug.py radio vfo on, radio freq F, radio bw 25 for a 25 kHz station).

Look for Proves If not

A CONFIG_AUDIO_PROBE build lets rfoundry_debug.py aprobe reg|wreg 4 REG [VAL] read and write HR_C6000 registers live.

5. DMR receive, transmit

DMR receive works on UHF and VHF (2026-11-02, a simplex group call, CC 1, slot 1, from another radio at about -70 dBm): headers, terminator and every voice burst, played clearly. Three fixes, found in this order (hardware-md9600.md 2.6, 4.2):

Fault Symptom with it
4:0xA1 = 0x80 from the init (bit 7 reserved, must be 0) no sync at all, though the chip's RSSI follows the signal
The tone pin (PC7) driven low into the reference oscillator no sync
4:0x01 bit 6 (receive I/Q swap) not matching the first LO's side: set on UHF, where the LO is below the signal an inverted spectrum: the odd sync, about one voice burst in six, no call

The first two were each needed for any sync while 0x01 was still wrong. Whether each is still needed with 0x01 right wasn't tried; both match what the manual and the radio's own start-up do.

Transmit, UHF, 5 W into a dummy load, a CONFIG_MD9600_TX and CONFIG_MD9600_DMR_TX build (2026-11-03), received by the SDR bench:

Check Result
DMR call, 3 s every burst decoded: headers, voice A-F, terminator, CC 1, BER 0. Carrier off between bursts (over 26 dB down) once T5 switches per burst (19.8)
FM carrier within 1 kHz of the channel, steady through the key
CTCSS 100.0 Hz 368 Hz deviation at 12.5 kHz, 754 Hz at 25 kHz on UHF; 380 / 758 Hz on VHF; DCS D023N +-385 / +-399 Hz (test_fm_tx_ctcss, test_fm_tx_bandwidth)
DCS D023N +-700 Hz, 0.30 s turn-off tail (test_fm_tx_dcs); inverted until MD9600_SUBTONE_TX_INVERT

Transmit stays off in the build until the power levels are checked.
