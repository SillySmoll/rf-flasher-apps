Feature matrix

Every feature, the build switch it sits behind (CONFIG_<switch> in config/features.mk, build-config.md), what it costs in flash on the ARM radios, and where it's built by default.

  • Bytes = default image minus the image with that switch off (tools/ci.sh builds each switch off), flash bytes. A parent switch's figure includes its children (turning FM off also drops VOX, APRS, ...).
  • Figures from tools/ci.sh at 3ec14e3 (2026-10-11).
    • DM-1701: plain build (LTO off), default image 340,680 B of 344,064 B (3,384 free). Since USRP (2026-10-13) the default build uses link time optimization: 330,824 B (13,240 free). The per-feature figures stay the plain ones.
    • MD-380: link time optimization on (LTO=1 LTO_3P=1, its default), default image 279,444 B of 281,668 B, the region it had then. With LTO a switch also changes what gets inlined elsewhere, so small MD-380 figures are approximate. Since the codec moved the region is 464 KB, and since every codec window moved into sector 11 848 KB; the switches that were off for flash are on. The per-feature figures stay the 2026-10-11 ones.
    • * = off by default; measured by turning it on in the DM-1701 build (main c0022b4).
  • Radios: which switches each radio builds by default is in Built by default on each radio, generated from the build. A — in a bytes column means not built there, so not measured.
  • A mark in the Built by default table is not a statement that the feature works. ● means the switch is on in that radio's default image, nothing more. A feature can be built in and still do nothing on a radio, or never have been tried on it. What has actually been checked on each radio is in Checked on each radio below.
  • The DM-32UV builds with csky-elf GCC; its sizes aren't in the per-feature tables (ARM only for now); its whole images are at the end.

Checked on each radio

Generated from the bring-up records in testing/results/, by the status rule of tools/bringup.py status. "pass" means a recorded run (tools/bringup.py run) passed the feature's required tests. "(seed)" means the evidence is the board's seed record: a check the docs recorded before the board's first run. "needs re-run" means the feature's spec or source files changed since that check; the result shown is the old one. "not recorded" means no record covers the feature on that radio: it is built in and host tested, and should be treated as unverified. "off" is off in the default build, ✕ not available. A radio's checklist with the required tests is tools/bringup.py list --radio <id>.

Built by default on each radio

● on in the radio's default image · ○ off by default (it builds when switched on) · ✕ the radio's hardware can't do it: the board or its platform lists it in BOARD_UNSUPPORTED with the reason (config.mk) · … the hardware can, but the radio's driver or glue isn't written yet (BOARD_NOT_WRITTEN) · ? off, and no source says yet whether the radio has the part it needs (board.toml [hardware] unconfirmed). The rule: build-config.md. From each board's make print-config. A switch that needs hardware some radios lack (hardware in tests/hil/features.toml) is never ○. The last two rows are not switches. Voltage reading: what the radio measures, its battery, its DC input (Supply) or none (board_volts() in hal/board.h). Clock: whether the radio's real-time clock keeps time through power-off (board.toml [hardware] clock; ? = not known yet). No driver reads the clock yet (radio-features.md 5.6).

DM-32UV

The DM-32UV has 880 KB of code space, so RAM limits it: 165,612 bytes above the stock codec's RAM window and 27,868 below it (RAM_LO). Its network is PPP on the programming cable (NET_PPP), on by default with the IP gateway and every service, TCP_CONNS=3 (boards/dm32/config.mk). It fits because the state the core marks RFOUNDRY_CPU_RAM lives in RAM_LO (hardware-dm32.md 17.1). Measured with csky-elf GCC 14 (bytes of the image, RAM of the linker's regions; the RTOS heap, 40 KB with every task stack, is inside the used part):
