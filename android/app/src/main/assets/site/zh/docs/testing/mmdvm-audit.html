MMDVM implementation audit (2d45a21)

An audit of the MMDVM modem implementation at commit 2d45a21 against docs/spec/mmdvm-protocol.md: its section 7 test list and the per-client needs of a standard host, the bench tools and the behavior of the aftermarket firmware. Done by reading the code; nothing was run on a radio.

Files: core/hotspot/{mmdvm.c,mmdvm.h,hotspot.c,hotspot.h}, the carried-over hotspotUplink.c, hotspotData.c, dmrDataFrame.c, core/hostlink/hostlink.c, drivers/usb/{usb_device.c,tusb_config.h}, platform/stm32f4/usb.c, tests/host/mmdvmTest.c, tools/mmdvm_probe.py, and TinyUSB 0.21.0 (third_party/tinyusb) where its behavior matters.

Severity:

  • Blocker: the feature can't work on the radio.
  • High: a supported client fails or gets corrupt data.
  • Medium: a client misbehaves, loses data now and then, or fills its log.
  • Low: differs from the spec with little effect.
  • Info: confirmed correct, or the spec should change.

Status (2026-10-10, branch agent/hotspot-net)

The findings below are as written at 2d45a21. Where they stand now, checked against the code and the host tests (nothing below has been run on a radio since):

Found since:

  • H-1 (HIL test, fixed): "hotspot entered through the debug link" failed with hs.enter_attempts=2, hs.running=0. The test's MMDVM client opened the port with pyserial's default DTR set; closing it dropped DTR, and the host link leaves hotspot mode on that edge (spec 5.1). By the time the debug link looked, the session was over. hs.enter_attempts counts every session since boot, so 2 meant two sessions that had each taken the modem, not two refused attempts. The radio core path was reproduced on the host (a DMR channel, the radio task above and below the host link task in priority): the modem is taken on the first frame or on the retry 1 s later. Fix: tests/hil/test_hotspot.py opens with DTR clear (as a Windows host may) and checks the slot 2 space, hs.running and hs.starts; new view keys hostlink.left (why the last session ended), hs.starts, hs.stops.
  • SFR mode: built behind CONFIG_SFR (docs/spec/sfr.md): spec 6.1-6.4 answered by core/hotspot/hotspotSfr.c, host-tested by hotspotSfrTest. The on-air repeat needs per-burst RF switching in the driver (sfr.md 3).
  • Network transport: MMDVM over UDP 3334 in the USB network personality (docs/spec/usb-network.md); the DTR rule does not apply there, the 20 s idle timeout does.

Updated per-client view: A standard host on Linux and Windows should work for voice and data in simplex; CW ID keyed on boards with tx_tone (the DM-1701 so far; host-tested only).

Summary

The protocol responder is sound:

  • framing, long-frame skipping and resynchronization;
  • protocol 1 version and status layouts;
  • SET_CONFIG and SET_FREQ ACKs, and SET_MODE accepted before SET_CONFIG;
  • downlink classification from the burst itself when the control byte is 0;
  • idle and PI bursts dropped without a NAK;
  • one call per transmission, keyed on the host's terminator, with back-to-back calls held behind each other;
  • NAK 5 with no wraparound when the buffer is full;
  • every header sent up, late entry, DMR_LOST 500 ms after the last burst;
  • the TX status bit;
  • nothing sent before the host's first command.

What needs fixing:

  • On the radio the hotspot can't start: no board registers the radio operations (A-1).
  • A host that clears DTR (a Windows host) knocks the radio out of hotspot mode on every poll (A-2).
  • Uplink voice bursts B-F have a malformed EMB and zeroed embedded signaling (A-3).
  • The uplink silence fill doesn't handle a superframe boundary (A-4).
  • DMR_SHORTLC, which a standard host sends on every call even in simplex, gets a NAK (A-5).
  • SEND_CWID gets a NAK (A-6).

1. Findings

A-1 Blocker: no board wires the hotspot to the radio core

  • Where: core/hotspot/hotspot.h:43 (hotspot_set_radio). The only caller is tests/host/mmdvmTest.c:332. Without it, hotspot_start() returns false (hotspot.c:270-272), and mmdvm.c:281-283 tries again on every frame.
  • Spec: 2.4 (space), 2.8 (DMR data), 7.4 and 7.5. The hotspot must take the modem and run.
  • Code: on the radio, GET_VERSION is answered, but status always reports slot 2 space 0 and every DMR_DATA2 gets NAK 2. A host logs a NAK for every frame of every network call.
  • Fix: the radio core implements the radio operations: enter, set_freq, set_power, leave, carrier and changed. enter stops FM and the DMR call stack and hands over the modem; carrier comes from the receiver's noise level. Register them at startup on every board that builds the hotspot. Until then, the description or the docs should not claim the hotspot works.

A-2 High: hotspot mode is left whenever DTR is clear

  • Where: core/hostlink/hostlink.c:172 (!port->connected()). connected is TinyUSB's DTR test (drivers/usb/usb_device.c:170-173). tools/mmdvm_probe.py:41 sets DTR for this reason.
  • Spec: 5.1. Don't gate anything on DTR. A host on Windows may open the port with DTR cleared. Test T-USB-2.
  • Code: with DTR clear, the first frame enters hotspot mode and is answered, and then the next pass of the task calls leave_hotspot(). That resets the configuration (mmdvm_end) and gives the modem back. Every frame enters and leaves again, so SET_CONFIG and SET_FREQ never stick and calls can't work. Linux and macOS raise DTR on open, so hosts there aren't affected.
  • Fix: never require DTR. Leave hotspot mode only after 20 s without a frame (already there), on USB unmount or suspend, on the user's exit, or on a DTR drop from set to clear (a POSIX host closing the port). Never because DTR has not been set. TinyUSB 0.21.0 keeps sending while DTR is clear (its TX FIFO only becomes overwritable, cdc_device.c:427-432), so nothing else needs DTR.

A-3 High: uplink voice B-F carry a wrong EMB and empty embedded signaling

  • Where: core/hotspot/hotspot.c:148-169 (voice_to_frame).
  • Spec: 2.8, modem to host. The 33 bytes must be a well-formed burst: correct EMB (color code, LCSS, QR(16,7) parity) and the embedded signaling for B-E made from the call's LC, as the aftermarket firmware did. Test U-10.
  • Code: the EMB's 7 information bits are set, but its 9 parity bits and all 32 embedded-signaling bits are 0. With zero parity the EMB doesn't give the color code and LCSS the burst should carry. Then:
    • A host's late entry fails.
    • Embedded fragments are collected in the wrong order.
    • Talker alias and in-call GPS from the sender never reach the host.
  • Fix:
    • Build B-F the way a transmitter does. The EMB is color code, PI 0 and the LCSS of the position, with QR(16,7,6) parity per ETSI TS 102 361-1 B.3.2 (not in core/dmr/fec yet: add it there, clean, from the standard).
    • The embedded bits of B-E are the four fragments of the call's LC (dmr_emb_lc_encode in core/dmr/call/dmr_lc.h already makes them). F carries null embedded signaling.
    • When the modem reports a decoded embedded LC that differs (talker alias, GPS: FLCO 4-7), send that superframe's fragments for it, so the alias reaches the host.
    • Add a host test that decodes the uplink EMB and embedded LC with the clean decoders.

A-4 Medium: uplink silence fill skips bursts across a superframe boundary

  • Where: core/hotspot/hotspot.c:722-726. The fill runs from the first missing position up to, but not including, the received burst's position, by increasing position only.
  • Spec: 2.8 and gotchas 8.5. Missed bursts are filled with silence at their positions, so the B-F sequence the host expects carries on. hotspotUplink.h:48 and hotspotUplink.c:228-238 give the fill range modulo 6.
  • Code: when the range wraps (E received, then F and A missed, then B), nothing is filled. B arrives right after E, a host drops it and the rest of the superframe (360 ms of audio).
  • Fix: fill every position from the first missing one, stepping modulo 6, up to the received burst's position. An A in the fill gets the voice sync, as now. Add a host test with a wrapped gap.

A-5 Medium: DMR_SHORTLC gets NAK 2

  • Where: core/hotspot/mmdvm.c:308-311.
  • Spec: 2.10. A standard host sends DMR_SHORTLC around every call, in simplex too. Accept and ignore it, with no NAK. Test D-8.
  • Code: NAK 2. A warning per call in the host's log, shown by Pi-Star style dashboards.
  • Fix: take DMR_SHORTLC of any length silently (no ACK needed).

A-6 Medium: SEND_CWID gets NAK 2

  • Where: core/hotspot/mmdvm.c:312-313.
  • Spec: 2.11. In idle, ACK it and send the callsign in Morse on FM, with the TX bit set while keying. In any other state, NAK 5.
  • Code: always NAK 2. A standard host with CW ID enabled logs a NAK every time, and no station ID goes out. The operator may count on that ID for licensing.
  • Fix: implement CW ID per 2.11: accept only in idle, ACK, key FM, send the Morse (about 20 wpm), keep the TX bit set until done, then restore the DMR setup fully (gotchas 8.13). Until then, list it as a limitation in the feature matrix.

A-8 Low: slot 1 space reported as 0 in simplex (spec says 10); no SFR hook for it

  • Where: core/hotspot/mmdvm.c:180.
  • Spec: 2.4 says the constant 10. 6.2 says both space bytes carry the outbound slot's space in SFR mode.
  • Code: 0.
    • A standard host then never writes DMR_DATA1. That is harmless, even better, since it would only get NAK 2.
    • The bench tools only print it.
    • Confirmed deviation, accepted: the spec will say "0 or 10 in simplex".
  • Problem left for SFR: the extension interface (mmdvm.h:123-129) can append bytes and OR flags, but can't set offset 7. When SFR is ported with an outbound TS1, a host that writes DMR_DATA1 gated on offset 7 would never send.
  • Fix: keep 0 in plain simplex. When SFR is on, report the outbound slot's space at offsets 7 and 8 (an extension hook for the space values).

A-9 Low: no RSSI after uplink bursts

  • Where: core/hotspot/hotspot.c:171-179. Frames go up with length 37.
  • Spec: 2.8 and 5.4. Optional. The aftermarket firmware sent 2 bytes (00, then the AT1846S register 0x1B high byte). On that raw scale, dBm = raw − 151 at 300 MHz and up, −164 + raw × 32 / 27 below. Test U-8.
  • Code: none.
  • Fix: when the modem reports an RSSI for the burst (rssi_dbm in dmr_burst_t is non-zero), send two bytes after the burst (frame length 39), big endian: 00, then the raw value on the AT1846S scale. Use the raw reading directly if the board can pass it, otherwise invert the formula above for the band in use. Leave them off when the RSSI is unknown. On radios with another RF chip, document the scale.

A-10 Low: no DMR_LOST when SET_FREQ interrupts a call being heard

  • Where: core/hotspot/hotspot.c:331-355. The uplink call is reset with no DMR_LOST.
  • Spec: 2.7 and test C-16. If an uplink call is open, send DMR_LOST2 before the SET_FREQ ACK. A host may otherwise keep such a call open.
  • Code: silent reset. A standard host doesn't retune in operation, so the effect is small.
  • Fix: if the uplink call is open when SET_FREQ arrives, send DMR_LOST2 first, then reset, retune and ACK.

A-11 Low: SET_MODE idle doesn't stop a transmission

  • Where: core/hotspot/mmdvm.c:245. Only the state byte changes.
  • Spec: 2.6 and test D-12. Idle stops new traffic for TX, ends a call in progress with a terminator within a superframe, clears the queue, and the TX bit clears once off air.
  • Code: a buffered or running call carries on. A standard host sends idle only after its mode hang (3 s after network traffic), so it doesn't normally hit this.
  • Fix: on SET_MODE idle, end a call in progress (our terminator), drop what's queued, then ACK.

A-12 Low: SET_MODE and SET_CONFIG refuse POCSAG (06)

  • Where: core/hotspot/mmdvm.c:194 and :237.
  • Spec: 2.5 and 2.6. Accept 06, keep receiving, report POCSAG space 0 or 1, never transmit pages.
  • Code: NAK 4. A host with POCSAG enabled (the Pi-Star default) logs a NAK each time a page arrives.
  • Fix: ACK 06 and treat it like DMR for reception; leave POCSAG space at 0.

A-13 Low: values the spec says to NAK are accepted, and vice versa

  • Color code: above 15 is masked to 4 bits instead of NAK 4 (mmdvm.c:201; test C-4). Fix: NAK 4.
  • DMR_DATA length: payloads longer than 34 bytes are accepted (mmdvm.c:255; test D-6). Fix: NAK 4 unless the frame is exactly 37 bytes.
  • SERIAL and TRANSPARENT: get NAK 1 (mmdvm.c:332-336). The spec says drop silently (2.12): hosts send them for a Nextion on the modem port and for transparent data, and log every NAK. Fix: drop both silently, as QSO_INFO already is.
  • FM_PARAMS1-4: get NAK 2. A host configured with FM sends them during startup and stops on the NAK The spec says ACK and ignore (2.14). Fix: ACK and ignore.

A-14 Low: no margin in the reported space

  • Where: core/hotspot/hotspot.c:797-807. Space is free ring places, minus 1 while a call is open.
  • Spec: 2.4. Report the free count minus at least 2 for frames already written while the status was on its way.
  • Code: a margin of 1 (the open-call terminator place) plus the host's own rule of never using its last place. That is enough in steady state. At the start of a call the host writes up to the full reported count in one clump, and frames in flight can produce a NAK 5 (a lost frame) at the edge.
  • Fix: subtract one more place. Test D-5 with a host that writes right up to its limit.

A-15 Medium (latent): enter is attempted inside every frame's handling

  • Where: core/hotspot/mmdvm.c:281-283.
  • Spec: 2.4 and 3.1. Status replies within tens of milliseconds; the version reply within about 300 ms.
  • Code: today hotspot_start() fails at once (A-1). Once wired, the radio core's enter (stopping FM and the DMR call stack, a retune) runs before every reply for as long as the radio refuses (transmitting, in a menu, DMR disabled). If it blocks, it delays every GET_STATUS and can trip a host's 2 s reset.
  • Fix: enter must not block (post a request and return). Try it again at most about once a second, not per frame. Always answer GET_VERSION and GET_STATUS first.

I-1 Info: ZLP after replies that end on a 64-byte boundary

TinyUSB 0.21.0 sends the zero-length packet itself when a transfer ends on a packet boundary (third_party/tinyusb/src/class/cdc/cdc_device.c:521-522), and cdc_write flushes after each frame. The spec's requirement is met. Still run T-USB-1 on the radio.

I-2 Info: DMR_START gets NAK 2

mmdvm.c:308-311. A standard host sends DMR_START only in duplex, so no current client is affected. The spec says ignore it. Low priority: take it silently along with DMR_SHORTLC (A-5).

I-3 Info: DMR_LOST timing correct

DMR_LOST2 goes up 500 ms after a call's last burst of any kind (hotspotUplink.h:13, checked on every hotspot_poll, which runs at least every 5 ms). It isn't sent during a header run. That meets 2.9 and the bench's 0.4-0.8 s window. The host test (mmdvmTest.c, uplink section) checks 0 before and 1 after.

I-4 Info: TX status bit lifetime correct

hotspot_transmitting() (hotspot.c:809-812) is set from the first buffered frame, through the modem's transmission, until DMR_EV_TX_DONE. It also covers queued data lists and the modem's own transmitting state, and is derived from the modem state machine, not the PA (gotchas 3.1). Carrier detect is reported only while not transmitting. Confirm on air that TX_DONE comes after the terminator slot (gotchas 3.2, test D-11).

I-5 Info: confirmed against the test list

  • Framing:
    • F-1 to F-8 by construction: resync on bytes other than 0xE0, length below 3 resynced, long frames skipped whole, unknown command NAK 1.
    • F-9: nothing goes up before the first frame (the uplink runs only while the hotspot runs).
  • Version and status: V-1. S-1: 13 bytes, byte 3 = 02, byte 12 = 0; byte 7 differs, see A-8. S-3 and S-4 (overflow flags reported once). S-5.
  • Configuration: C-1, C-2 (SET_MODE DMR before SET_CONFIG is ACKed), C-3 (other mode bits ignored), C-5, C-7, C-8, C-9 (POCSAG frequency ignored, only the board's range applies), C-10, C-12.
  • Downlink:
    • D-1, D-2 and D-3 (control 0 classified from sync and slot type; idle and PI headers dropped without a NAK; one header or eight).
    • D-4 (the old call ends with a terminator, the new one keys again).
    • D-5 (NAK 5, no wraparound, TX overflow reported once).
    • D-7, D-9 and D-10 (data lists and lone CSBKs).
    • DMR_ABORT takes no reply and drops the queue.
  • Uplink: U-1 (every header), U-2 (late-entry header made from the embedded LC, silence from A), U-4, U-6, U-7 (data only within a data transmission), U-9.
  • Timing: T-4 (20 s idle timeout, configuration forgotten).
  • Extensions: X-4 and X-5 in a build without the extension (NAK 1), and through the hook.
  • Transport: frames are written whole from the host-link task only, so replies and uplink frames never interleave.

T-1 Test coverage gaps (tests/host/mmdvmTest.c, tools/mmdvm_probe.py)

Missing:

  • A host test decoding the uplink EMB and embedded LC (A-3).
  • A wrapped uplink gap (A-4).
  • DMR_SHORTLC, SEND_CWID, SERIAL, TRANSPARENT and FM_PARAMS answers (A-5, A-6, A-13).
  • DMR_LOST before the SET_FREQ ACK during a call (A-10).
  • SET_MODE idle mid-call (A-11).
  • RSSI bytes (A-9).
  • A host link test with DTR clear (A-2).
  • A slow enter (A-15).
  • The probe always raises DTR. Add a --no-dtr run (T-USB-2).
